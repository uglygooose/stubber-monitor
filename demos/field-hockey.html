The game loop

Every game is the same three steps, sixty times a second:

1. read input — where is the mouse, which keys are down
2. update — move the ball, move the keeper, check collisions
3. draw — wipe the canvas and paint everything in its new position

requestAnimationFrame(loop) at the bottom of the function asks the browser to run it again on the next screen refresh. That single line is what makes it a game rather than a picture.

How the ball moves

The ball stores a position (x, y) and a velocity (vx, vy). Each frame:

x += vx and y += vy move it,
vx *= friction slows it down,
vx += curve bends it while you hold an arrow key.

That is genuinely all of it. Real physics engines are this same idea repeated with more forces.

Collisions, cheaply

The keeper is a rectangle, the ball is a circle. To test a hit, find the closest point on the rectangle to the ball's centre, then check whether it is nearer than the ball's radius. Two lines of Math.max/Math.min and one distance check — no library required.

Make it yours

Open this file in any editor and hunt for the CFG object near the top of the script. Change GOAL_W to widen the goal, add a third defender in spawnDefenders(), or set shake higher on a goal for more drama. Save, refresh, see what breaks — breaking it and fixing it is the whole job.
